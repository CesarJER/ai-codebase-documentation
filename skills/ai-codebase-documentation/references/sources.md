# Sources and Provenance

This skill adapts established documentation practices rather than mandating a framework. These are maintainers' references; do not browse every source on every documentation task. Project-specific implementation claims still require project evidence.

The pages below were checked on 2026-10-07. Availability at that time does not make a source a frozen standard.

| Primary source | Practice adapted in this skill |
| --- | --- |
| [Google developer documentation style guide](https://developers.google.com/style) | Project conventions first; clear, consistent writing for the actual reader |
| [Google code samples](https://developers.google.com/style/code-samples) | Introduce examples, follow relevant code style, and make omissions explicit |
| [Diátaxis](https://diataxis.fr/) | Distinguish learning, task completion, lookup, and understanding without prescribing a site implementation |
| [Write the Docs: Docs as Code](https://www.writethedocs.org/guide/docs-as-code/) | Use shared versioning, review and automation workflows near the code |
| [GitLab documentation style guide](https://docs.gitlab.com/development/documentation/styleguide/) | Precise, direct documentation and project-specific editorial conventions |
| [GitLab AI instruction files](https://docs.gitlab.com/development/documentation/ai-instruction-files-documentation/) | Reuse authoritative instruction sources rather than duplicating inconsistent standards |
| [Microsoft code examples](https://learn.microsoft.com/en-us/style-guide/developer-content/code-examples) | Relevant, understandable examples with safe handling and appropriate explanatory context |
| [C4 diagrams](https://c4model.com/diagrams) | Select architecture views by the understanding needed; avoid unnecessary levels |
| [AWS ADR best practices](https://docs.aws.amazon.com/prescriptive-guidance/latest/architectural-decision-records/best-practices.html) | Record decision context and consequences; retain and supersede accepted history |

The practical evidence labels, severity thresholds, diff-impact table, graph-freshness checks, execution-effect review, and templates are guidance designed for this skill. They are not requirements claimed to come from the sources above.

For historical decision context, the existing supplementary [AWS ADR FAQ](https://docs.aws.amazon.com/prescriptive-guidance/latest/architectural-decision-records/faq.html) remains useful; it was not rechecked in this revision.

When a task depends on a current external API, version, or standard, consult the matching authoritative source rather than treating this summary as proof. Keep search queries free of private code, credentials, personal data, or deployment identifiers.
